# LearnTrace（假資料版 MVP）

碩士論文研究系統：**課程導向學習系統中共同學習困難的訊號辨識與教師回應機制：設計研究**。

這一版只用假資料：30 位虛構學生、RC 電路 3 個概念、每概念 2 題驗證小考。不串外部 AI，不收真人資料，沒有登入。

## 執行

只需要 Python 3.10 以上，不用安裝任何套件。

```bash
python3 -m learntrace.server --reset A    # 開啟 http://127.0.0.1:8000
python3 -m unittest discover -s tests -t . # 跑全部測試
```

`--reset` 可選：

| 情境 | 內容 |
|---|---|
| `A` | 「時間常數 τ 的意義」多人卡關，確認小考資料後應出 1 張洞察卡 |
| `B` | 沒有明顯卡關，不出卡 |
| `blank` | 從教師事前預測開始，手動操作全部流程 |

A、B 都已模擬學生學習與小考，停在「驗證小考進行中」。接著用教師身分確認小考資料、查看洞察卡、送出回應，再用研究者身分追溯。

## 驗收標準

> 從學生完成單元，到教師送出回應，整條流程可以跑完；洞察卡數字可追溯到事件紀錄。

- `tests/test_http.py` 透過 HTTP 從空白開始走完整條流程，並檢查追溯結果。
- 研究者頁面（`#/research`）逐一列出卡片上每個數字對應的 `event_log` 紀錄，並標示是否一致。

## 四個模組

| 模組 | 主要規則 | 程式 |
|---|---|---|
| 同意與研究代號 | 研究表只寫入 `consented`；不同意者只留營運層進度，提問與小考作答不寫入資料庫 | `services.set_consent`、`research_code` |
| 學生單元頁 | 四種訊號同一學生、同一概念、同一輪最多記 1 次；`quiz_wrong` 由伺服器判定第一次作答；`unit_completed` 由伺服器檢查條件後建立 | `answer_practice`、`level_down`、`not_understood`、`submit_question`、`request_unit_complete` |
| 驗證小考 | 教師命題並鎖定；學生端看不到答案與概念；`quiz_attempts` started → submitted／expired；任一題未作答則該概念 `quiz_score` 為 null | `lock_quiz_items`、`quiz_start`、`quiz_submit`、`export_rows` |
| 教師流程 | 事前預測（2–3 個、送出即鎖）→ 開放小考 → 小考資料確認（只給人數）→ 洞察卡快照 → 回應（必填原因、送出即鎖、可補記） | `submit_predictions`、`confirm_quiz`、`generate_cards`、`respond_card` |

## 資料與鎖定

- 三個 SQLite 檔：`research.db`（研究與教師資料）、`ident.db`（帳號對代號）、`ops.db`（營運進度）。結構見 `learntrace/schema.sql`。
- 鎖定在資料庫端：觸發器拒絕修改或刪除已送出的預測、事件、小考作答、洞察卡、教師回應；已鎖定的教材與題目不能改；輪次階段只能往前一步。
- 時間一律由資料庫產生，不接受前端時間。
- 洞察卡門檻：任一訊號的學生至少 5 人，且達本輪可分析學生的 30%（無條件進位）。單一訊號少於 5 人只顯示「少於 5 人」；提問者少於 5 人不產生常見困惑摘要。
- 本輪可分析學生＝同意研究、完成指定單元、送出驗證小考。

## 正式收案前必須補上

這一版刻意沒有做，但正式收學生資料前一定要完成：

- 學校帳號登入（目前用 `X-Demo-Account` 標頭扮演角色，只適用假資料）。
- 問題原文與帳號對照表加密，並依倫理審查決定保存期限。
- 撤回同意的處理流程（依倫理審查核准程序）。
- 部署位置符合學校個資規定。
- 常見困惑摘要與 AI 建議改由外部 AI 產生時，只送去識別化文字與概念統計，並記錄模型與提示詞版本。

目前也不做：即時聊天 AI、語音、成就系統、個人學習報表、排行榜。
